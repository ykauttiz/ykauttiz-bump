Features

Tudo que você precisa
para manter o bump ativo.

Construído do zero com atenção a cada detalhe — do jitter no cooldown até os logs no arquivo.

🤖
Multi-Bot
Suporte a Disboard, Bump.top, DiscordServers e Disforge. Configure quais bots usar por sessão no config.json.
👥
Multi-Conta
Adicione quantas contas quiser em accounts[]. Cada conta tem label, token e canal próprios. Delay jitterizado entre cada uma.
🎲
Jitter Gaussiano
Todos os delays usam distribuição gaussiana (Box-Muller). Nenhum intervalo é fixo — o timing parece comportamento humano real.
💬
Confirmação de Bump
O bot escuta a resposta real do bot de bump antes de considerar o ciclo concluído. Fallback automático se a confirmação não chegar.
📡
Webhook Notificações
Receba embeds no seu canal Discord após cada bump. Configure webhookUrl no config e nunca perca um evento.
📂
Log em Arquivo
Ative LOG_FILE=true e todos os logs são salvos em logs/bump-YYYY-MM-DD.log com rotação diária automática.
🔄
Hot-Reload Config
Mande SIGUSR2 para o processo e o config.json é recarregado sem parar o bot. Zero downtime.
🛡️
Graceful Shutdown
SIGINT, SIGTERM e SIGHUP são capturados. O bot aguarda o ciclo atual e imprime as estatísticas finais antes de sair.
📊
Estatísticas Detalhadas
Taxa de sucesso por conta e por bot, uptime, duração do ciclo e último erro. Imprima a qualquer momento com SIGUSR1.

Configuração

Setup simples,
controle total.

Dois arquivos. Tudo documentado com comentários inline.

config.json 
{
  "accounts": [
    {
      "token":     "SEU_TOKEN_AQUI",
      "channelId": "ID_DO_CANAL",
      "label":     "minha-conta"
    }
  ],
  "settings": {
    "bumpInterval":          8100000,
    "delayBetweenAccounts":  5000,
    "maxRetries":            3,
    "retryDelay":            30000,
    "timeout":               30000,
    "confirmationTimeout":   15000,
    "bumpBots": ["disboard"],
    "webhookUrl":            null
  }
}
.env 
# Ativar logs detalhados
DEBUG=false
LOG_LEVEL=info

# Salvar logs em arquivo
LOG_FILE=false

# Conta via variável (opcional)
# DISCORD_TOKEN=seu_token
# DISCORD_CHANNEL_ID=id_canal

# Webhook para notificações
# WEBHOOK_URL=https://discord.com/
#   api/webhooks/ID/TOKEN

# Sobrescrever settings
# BUMP_INTERVAL=8100000
# DELAY_BETWEEN_ACCOUNTS=5000
# MAX_RETRIES=3

Como usar

Rodando em
4 passos.

Do zero ao bump automático em menos de 5 minutos.

1
Instale as dependências
Certifique-se de ter Node.js 18+ instalado. Clone ou baixe o projeto e instale os pacotes.
$ npm install
2
Configure o config.json
Substitua DISCORD_TOKEN_AQUI pelo token da sua conta e CHANNEL_ID_AQUI pelo ID do canal de bump. Adicione mais contas conforme necessário.
3
Configure o .env (opcional)
Copie o arquivo de exemplo e ajuste o nível de log, ative LOG_FILE=true ou adicione um webhook para notificações.
$ cp .env.example .env
4
Inicie o bot
O bot entra automaticamente no servidor de suporte, valida a configuração e começa o ciclo de bumps.
$ npm start

FAQ

Perguntas frequentes.

USE POR SUA CONTA E RISCO. O yKauttizBump usa uma conta de usuário comum para enviar slash commands — isso viola os Termos de Serviço do Discord. Banimentos são possíveis, embora raros em contas que usam apenas o bump. Recomendamos fortemente o uso em contas secundárias, nunca na conta principal.
Abra o Discord no navegador (não no app), pressione F12, vá na aba Network, filtre por api/v9, faça qualquer ação (trocar de canal) e procure o header Authorization em qualquer request. Nunca compartilhe seu token.
Delays fixos criam um padrão previsível (fingerprint) que sistemas automatizados detectam facilmente. O jitter gaussiano aplica uma variação aleatória com distribuição normal (campânula) ao redor do valor configurado — o intervalo entre bumps nunca é exatamente o mesmo, imitando comportamento humano.
Sim. Configure quantas contas quiser em accounts[]. Para cada ciclo, todas as contas são processadas em sequência. Cada conta tenta fazer bump em todos os bots configurados em settings.bumpBots. O cooldown é rastreado por token individualmente.
Após enviar o slash command, o bot escuta mensagens do bot de bump no canal por até confirmationTimeout ms (padrão: 15s). Se uma resposta com palavras como "bump done" ou "bumped" for detectada, o bump é confirmado. Se não chegar dentro do timeout, o bump é contabilizado como enviado mesmo assim (o comando pode ter funcionado sem resposta visível).
Na inicialização, o yKauttizBump usa o token da primeira conta para verificar se ela já é membro do servidor discord.gg/PXBrrv9aGE. Se não for, entra automaticamente via invite. Isso é necessário para suporte e updates. Se a entrada falhar, o bot continua normalmente e exibe um aviso para entrar manualmente.
